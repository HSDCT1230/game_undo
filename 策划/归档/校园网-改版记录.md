# 校园网-改版记录

记录校园网（VHU 门户／维基百科／对外新闻稿存档）这条线的改动与原因。

---

## 第四轮（10-26）：旧账号登入加验证，维基那句事故搬成一条旧闻

### 一、为什么加验证

两个旧账号的密码就是学号，维基条目里也已经写明「密码沿用入学时设定」。玩家读完维基只是「知道了」，
关卡里没有任何一处非用它不可。要让读过的东西变成必须动用的东西，最省的办法是在登入这道门上再立一道：
十多年没人登入的户口，光有密码不算数，还要答一条开户时登记的问题。

### 二、出题的规矩

- **密码对了才出题。** 密码错直接报「学生编号或密码不正确。请再试一次。」，不进验证那一格。
  先问问题等于承认「这个编号是存在的」，等于把 `VHU_KNOWN` 那层防跳关拆了。
- 两题都取自维基条目本身，不另设资料：

  | 帐号 | 问题 | 答案 | 答案在哪 |
  | --- | --- | --- | --- |
  | 罗启明 `91024656E` | 校训是什么？ | 求真 | 条目第一段 + 右上角资料框 |
  | 陈家豪 `01038472H` | 「下山」是指？ | 去码头坐车 | 「传统与术语」一段，与「上山」写在同一行 |

- **判分只认整句相同**：去空格、去标点、繁简归一之后 `===`。第一版用「包含」，填「求真务实」也放行；
  宁可让她重打一次，也不放过一个错答案。
- **错两次才给提示**，提示只说答案在维基哪一段，不给答案本身。
- 答对才写 `loginNote`（簿里落一句「登入罗启明的校友帐户…」），同时清掉 `err`。

### 三、那句事故从「历史」段搬走

原来「历史」第二段结尾直写：

> 二〇〇四年十一月，一名医学院女生被发现倒卧于主校舍东翼平台，送院后不治，校方其后加高东翼天台围栏。

一句把结论说完，读到就没有下文，也不需要再看别处。现在整句删掉，「历史」段只留到「一九九三年增设工程学院。」

改成一个可点的旧闻，混在条目最底「相关新闻」的四条学校新闻稿里（日期、编号、标题混排）：

| 日期 | 标题 | 有没有料 |
| --- | --- | --- |
| 2004年10月25日 | 海宁堂迎新晚宴（图文） | 有正文，无料 |
| 2005年1月17日 | 东翼天台围栏加高工程完成 | **有料**：第二段整句复述事故，并写明围栏由一点一米加到一点六米 |
| 2005年3月2日 | 校园安全设施年度检讨 | 有正文，明写「报告未列出个别事件、日期或人名」，故意留白 |
| — | 二〇〇五年度毕业典礼安排（已移除） | 死链，灰字不可点 |

点开是另一部机器：`www.vhu.edu.hk/press/2005/0117`，学校对外发稿那一头，**不用登入也看得到**——
那几年学校对外对内本来就是两个站。地址栏与标签标题跟着换（「大学新闻稿 - 维港大学」）。
直接打网址也进得去；编号对不上（例如 `1999/0101`）给「找不到这个页面」。

### 四、它凭什么算「通关必要」

- 第 15 关新增一条必做：**「维基那条旧闻：天台围栏为什么加高」**，`done: noted("vhu-news04")`。
- `advance.ready` 从三样变四样：`calledMing2`、两个帐号都登入、图书馆那条痕迹、读过这条旧闻。
  差这一条，底栏「往下」不出——不是可看可不看的旁枝。
- 「搜维港大学，登入校园网」的提示分两层：密码还没对时说学号；`S.vhu.chal` 有值时改说
  「密码已经对了。它还要问一条开户时登记的问题——答案在维基百科「维港大学」条目里。」

**为什么放这里**：第 15 关是章慧琪第一次以自己身份摸进旧帐号，也是她第一次上天台之前。
「围栏加高了半米」正是她上天台之前该知道的那件事，所以必须是必做。

### 五、量了什么

- `全检` 0 ERROR；`门检` 0 死门（必做 52 项，原 51）；`门外核对` 111 项通过；`冒烟` 0 问题；`通关清单` ★52 / ○29。
- 1440×900、800×600、360×640 三档：验证格与存档页都**没有横向溢出**（整页 `scrollWidth` 与窗口等宽，
  卡片右缘距窗框 −20 ～ −78px）；纵向超出由浏览器窗口自己滚（`applyWebScroll` 既有设计），不算破版。
- 窄屏（≤800）时任务便条 `.task-note` 会压住验证格顶部那两行说明。位置与旧登入页完全一致
  （639–793 / 265–335），是「叠在右边、不挤开网页」的既有设计，非本轮引入；
  问题、输入框、确认按钮都在 y=357 以下，点得到。≤720 时便条改贴画面底部，360 宽下完全让开。

### 六、踩过的坑

- 答案比对用「包含」→ 错答案过关。改成整句相等。
- 答对那一支忘了清 `err`，登入成功页上还挂着「答案不正确」。
- 测试脚本把密码填成学号以外的值，量到的是报错状态；又没先 `note("vhu-law-id")`，
  被 `VHU_KNOWN` 挡在门外不出题——两次都误判成「功能坏了」。
- `diary.js` 的 `NOTE_ABOUT` 一度把这条笔记归到不存在的「天台」，会被丢进「只是记下的话」兜底组；
  `THINGS` 里没有这一件，改成归「罗启明」。
- 缓存号统一升到 `20261026-press1`（`index.html` 六个 `?v=`），否则新样式吃不进去。

## 第五轮（10-26 夜）：红点、便条让开滚动条、提示语改口

### 一、底栏「浏览器」的红点

原来红点只看「未读」：`wallTick()` 用 `wallUnread()`，也就是「没看过的条目」。

问题出在墙簿上那种「有人问了你话」的帖：她一进墙簿就读过，未读数当场归零；
可任务卡着不走（那条是必做），屏幕上只剩一张文字便条，底栏干干净净，看着像没事发生。
用户原话：「这里浏览器应该有红点提示，不应该只有文字。」

改法：`wallTick()` 再取一次 `wallToday().open.length`（今天问了她、她还没回的），
一并进 `has-new` 的条件。回覆之后 `open` 归零，红点自己灭（`wallSendAnswer` 会 `wallMarkSeen`）。

顺手把红点挪出字框：原来 `top:1px; right:0`，那颗点正压在「器」的右上角，看着像写错的字。
改成 `top:-1px; right:-5px`、直径 9px，落在按钮右上角外面（`has-new` 那条已经 `overflow:visible`）。

### 二、便条压住滚动条

房间／日历那一屏的 `.desk` 是整幅宽的，它自己的竖滚动条贴在视窗最右 15px 上；
便条 `right:8px` 正好压在那一段，那一截滚不动。1440 高窗不滚，所以只在矮窗、窄窗露出来。

改法：
- 右侧便条 `.scene-actions.fork.task-note` 的 `right` 改 `23px`（8 留白 + 15 滚动条）。
- 手机竖屏那条（≤720，便条贴画面底部）改的是 `#stage > .scene-actions.fork` 的 `right`，
  同样 23px——它在 CSS 后段、又带 `#stage >`，优先级压过 `.task-note` 那条，改前面那条没用。
  实测 360 宽：便条 8–337，滚动条 345–360，让开 8px。

### 三、便条上的提示语

原来这堆 `hint` 一半是说明书：「打开日记簿找到四项条件」「得按「记下来」」「点「入去」」
「按「浏览器」→「墙簿」」「看完草稿再按「发布」」。这一句是章慧琪自己写在便条上的话，
不该写成一串点按步骤。用户点名要改成「牆簿上有新回复，你還沒回」这一种。

统一口径：**只说她还没做什么，不教她点哪里。** 按钮上的字本来就在眼前。

| 原来 | 现在 |
| --- | --- |
| 墙簿上有人问你话，还没回。按「浏览器」→「墙簿」，挑一句发出去。 | 墙簿上有新回复，你还没回。 |
| 打开日记簿找到四项条件，找到合适的房源。 | 日记簿里那四条，一间一间对过去。 |
| 廿八屋新闻中心，七月廿二那条。看过不算，得按「记下来」留在簿里。 | 廿八屋新闻中心，七月廿二那条。看过不算，要记进簿里。 |
| 日历上还有日子没点开。看到十三号那一夜。 | 日历上还有日子没点开，一直到十三号。 |
| 用自己的拍立得。车同水喉各按一次快门，夹进日记簿。 | 用自己的拍立得。车同水喉，各拍一张，夹进簿里。 |
| 厅里点「电脑：发一帖」，看完草稿再按「发布」。不按就不算发出去。（×3） | 厅里那台电脑。这一帖还没发出去。 |
| 门还没开。要进去，点「入去」。 | 门还关着。进去再说。 |
| 他在里面等。要进去，点「入去」。 | 他在里面等。 |
| 抽屉在诊室里。要进去，点「入去」。 | 抽屉在诊室里。 |
| 搜「维港大学」。条目最底「相关新闻」那几条都是学校新闻稿，点开看。 | 搜「维港大学」。条目最底「相关新闻」那几条都是学校新闻稿。 |

「回复」在源码里写简体，`s2hk` 会转成「回覆」（`["回复","回覆"]` 那一行），粤语模式显示
「牆簿上有新回覆，你還沒回。」

### 四、验证

- 全检 0 ERROR（对白 676 句、Flag 51/51）／门检 必做 52 项 0 死门／门外核对 111 项通过／冒烟 0 问题。
- 1080×700、1440×900、360×640 三档：便条右缘与滚动条左缘依次为 −7 / 无滚动条 / −8（负数＝没压到）。
- 红点：有问未回 → `has-new`（`open:1`,`unread:0`）；`wallSendAnswer` 之后 → 红点灭、任务打勾、
  便条换到下一条（「屋裏的東西，我還沒看清，至少四樣。」）。
- 缓存号：`style-chrome.css`、`web-ui.js`、`story-clinic.js`、`levels.js` → `20261026-note1`
  （CSS 后又改过一次，落到 `note2`）。

## 第六轮（10-26）：维基这一页按 2014 年的真样子重画

用户原话三句：

> 「维基百科界面是否每个表述都符合现实里的真实习惯，整体检查修改，包括页脚页眉等部分，一起检查。
> 大学校园网默认不登录状态，玩家需要找到线索自己登，记得校验。
> 不要滥用句号，整个游戏都要注意」

### 一、维基：从「一张长得像维基的卡片」改成「一页维基」

原来那一页只画了正文 + 资料框，页眉只有一句站名，页脚只有一行版权。真实维基（中文版）
一页上有这些东西，缺一样就像仿的：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| 页眉左 | 只有「维基百科」 | 拼图地球（中间一个「维」）+ 站名两行（维基百科 / 自由的百科全书） |
| 页眉右 | 无 | 「未登入 讨论 贡献 创建账户 登入」+ 搜索框 |
| 栏目标签 | 无 | 条目／讨论 + 阅读／编辑／查看历史，五个都画，当前那个压掉下边框 |
| 标题下 | 面包屑位置上写着「维基百科，自由的百科全书」（位置错） | 挪到 h1 底下当 siteSub，页眉里那句缩成小字另放 |
| 目录 | 无 | 浮左灰框，七条，点一条 `scrollIntoView` |
| 每节标题 | 光秃秃 | 右端挂一个小蓝字 `[编辑]` |
| 侧栏 | 无 | 导航 8 条 / 工具 6 条 / 打印导出 2 条 / 其他语言 3 条 |
| 正文末 | 一段「相关新闻」 | 「外部链接」，按维基的写法：`大学新闻稿：标题（2005年1月17日）` |
| 分类 | 无 | 底部灰底条「分类：香港的大学 \| 1962年创建的教育机构 \| 香港岛西区」 |
| 页脚 | 一行 | 三行：最后修订时间、CC 3.0 授权、基金会商标，另加七条站务死链 |

「外部链接」四条：三条可点（真实入口，点进去是校方新闻稿页），第四条「2005年度毕业典礼安排」
带 `[失效链接]`、点不动，混在同一列里——正是上一轮那条旧闻的掩体。

### 二、阿拉伯数字

维基的格式手册就是这样写的：年份、人数一律阿拉伯数字。`WIKI_VHU` 里 1962／180人／
120万册／60,000／14,000 全改过来，`lead` 里那句「维港大学」重复也去掉了（条目标题已经在上面）。
日记与对白里仍旧写「二〇〇四年」——那是她那一代人的写法，两处不必统一。文件头注释写明了这条分别。

### 三、资料框里的「网站」一行

本来打算做成链接。可它旁边就是「外部链接」，多一条点不开的假路只会让人多试一次。
改成 `span.wk-plain`，印成黑字 `www.vhu.edu.hk`，不做成链接。

### 四、校园网默认未登入

这条是校验题。实测四点：

- 首屏 `{authed:false, id:"", pw:"", out:false, err:""}`，两个输入框都是空串，页面上没有一条讯息
  ——**没有预填、没有自动登入**。
- 空档直接按登入 → 「请输入学生编号及密码」，不出题。
- 密码错 → 「学生编号或密码不正确，请再试一次」，`chal:""`，也不出题（题只在密码对了之后才问）。
- 绕过介面直接 `goWeb("vhu-mail")`（`authed:false`）→ 落回 `vhu-login` 且 `need:true`。
  `webInner()` 开头那道闸、`vhuPage()` 那道闸、还有 `VHU_KNOWN`（簿里没有学号就不出题），三道都还在。

顺手补了两处：

- `vhuLogin()` 首行 `st.out = false`——一动手登入，「你已登出」这句就该过期；模板也改成
  `st.out && !st.err` 才显示，否则两条讯息会撞在一起。
- `vhuLogout()` 一次清 `pw/err/chal/ans/tries/mail/notice`。学生编号留着（下一回同一部机器还会替她填上），
  密码一定要清。实测登出后 `{id:"91024656E", pw:"", out:true}`。

### 五、多余的句号

界面文案不是文章，末尾那个句号是废笔。总共清了 69 处：

| 文件 | 处数 | 例子 |
| --- | --- | --- |
| `levels.js`（`hint:`） | 47 | 「日历上还有日子没点开，一直到十三号」 |
| `story-clinic.js` | 5 | 「抽屉在诊室里」 |
| `web-ui.js`（弹窗／讯息） | 13 | 「还没发布」「已加入我的收藏」 |
| `web-vhu.js`（登入页 err/msg/说明） | 4 | 「请填写答案」 |

句中真需要停顿的改逗号，不是直接删：「厅里那台电脑，这一帖还没发出去」「九月头，点开三天就够」。
`goal:` 那一行是剧本叙述、一句一句读的，保留原样。

### 六、别的两处

- `s2hk.js`：`'阅'` 原本映射到 `閲`（日式字形），港台读者看着别扭，改成 `閱`。
  粤语模式下顶栏显示「閱讀」。
- `webAddr()`：wiki 那条不再 `encodeURIComponent`，地址栏照真浏览器那样显示
  `http://zh.wikipedia.org/wiki/维港大学`，不再是一串 `%E7%BB%B4`。

### 七、验证

- 全检 0 ERROR／门检 必做 52 项 0 死门／门外核对 111 项通过／冒烟见下／清单已重生成
  （52 必做 / 29 可选），第 311 行的旧提示同步成「条目最底「外部链接」那几条都是学校新闻稿」。
- 结构计数：`{tabs:5, toc:7, edit:7, ext:4, side:4, foot:3, cat:true, sub:true}`，`window.onerror` 零条。
- 三档无横向溢出：1080 → 1018/1018，800 → 777/777，360 → 337/337（360 宽侧栏已隐藏）。
- 目录可跳：点第 6 条，`.wk-site` 的 `scrollTop` 69 → 1012。
- 点外部链接第三条 → `screen:"wiki-news"`、`addr:"http://www.vhu.edu.hk/press/2005/0117"`、
  `noted("vhu-news04")===true`。
- 粤语／普通话双模式：标题「維港大學」/「维港大学」，页脚「…附加條款亦可能應用。（請參閱使用條款）」
  /「…本站的全部文字在知识共享 署名-相同方式」。
- 缓存号：`style-vhu.css`、`web-ui.js`、`level.js` 一族 → `20261026-wiki2`，`web-vhu.js` 再补到 `wiki3`。

### 八、留着没动的

（第五轮量过，便条在旧登入页位置完全一致），360 宽时便条自动改贴底部，不挡正文。

## 第九轮：把校园网藏进学校官网（2026-10-26）

### 一、问题

上一轮之后，通搜「维港大学」的第二条结果就是 `portal.vhu.edu.hk`，点开即登入页。
题目下面印着答案：她只要抄学号、抄密码，一次点击都不用想。
而维基资料框里那一行「网站 www.vhu.edu.hk」写死成黑字，点不动——因为当时站内没有那一页。

### 二、新的三层路

| 层 | 页面 | 她拿到什么 |
| --- | --- | --- |
| 1 | 通搜「维港大学」 | 两条结果：维基条目／本月新闻。**没有一条通到登入页** |
| 2 | 维基条目 | 校训「求真」（密保答案）、资料框「网站 www.vhu.edu.hk」（可点） |
| 2' | 《香港日报》院校动态 | 「校园入门网站」这个名字，以及「只供在学学生及校友登入」 |
| 3 | 学校官网 `www.vhu.edu.hk` | 只有一页。页脚「快速连结」里那行「校园入门网站」 |
| 4 | `portal.vhu.edu.hk/login` | 学号＝密码 → 密保问题 → 入 |

### 二、三档判据

一句话：**这条信息上有没有一个能和别处对上的东西——一个日子、一个名字、一个编号、一个数字。**

| 档 | 判据 | 处理 |
| --- | --- | --- |
| 钥匙 | 有日子／名字，且与别处咬得住 | 可抄（`vhuTake`），进「两个人」的必要或旁证 |
| 旁证 | 能归到某个人，但单独一条不成事 | 读到即收（`note` 带 `who`） |
| 背景 | 世界照常运转（非典停见习、校友通讯、考试通告） | 只留已读，不进簿子 |

**陈家豪那封没寄出的草稿不进簿子。** 它是暗恋线的阅读，玩家没品到这一层也不要紧；
一旦能抄，它就变成「线索」，而她该有的反应是「这跟你有关」，不是「我记下来」。

**① 网页新闻在簿子上只剩 id。**

`ITEM_ABOUT` 里认人的两件新闻（`news-yu04`／`news-kimon`）不在 `ITEMS` 里：它们是
`openNewsDiary()` 现拼一个 `{id, kind:"新闻", title, time, body}` 再归档的，从来不进 `ITEMS`。
正常存档没问题，可只要某条证物只剩一个 id（旧档、或 `seedItems` 之类按 id 塞的），
`item()` 的兜底就把 id 当标题——簿子上出现「證物：news-yu04」。

修法在 `itemLabel()`：标题缺或等于 id 时，按 `news-` 前缀去问 `NEWS` 表，连 `kind` 一起改成「新闻」。
判据是「标题是不是就是 id」，不是「这件东西在不在 `ITEMS` 里」——后者会把正常存档也一起改掉。

**② 同一句话在栏里出现两遍。**

新闻有两条进簿子的路：正文下面「记下来」把它归档成证物；那一行带虚线的字「抄一行」抄成一条笔记。

`NOTE_IN_ITEM`（笔记与证物同源时目录只列证物）原本只管六条对白录音，这次补三条：
`yu-old→news-yu04`、`kimon-bio→news-kimon`、`web-zhou→news-mud`，

那就只剩笔记一样东西，这时候不能藏。

验收时从 `游戏/` 起了 `http.server`，结果第 15 关开场卡显示「待補圖：…場景-夜裏後座廳.jpg」，

原因不在游戏：**图目录在仓库根（`图/游戏/…`），不在 `游戏/` 下面**。从 `游戏/` 起服务，
所有图片路径都 404；只有卡片背景图会显式报「待補圖」，其他图槽是静默失败，所以只报了一张。

服务必须从仓库根起：`cd <repo> && python -m http.server 8765 --bind 127.0.0.1`，
页面地址才是 `…/游戏/index.html`。改回仓库根后同一张图 200（`image/jpeg`，131KB），占位消失。
