# 浏览器外壳与电话界面 · 改版记录

## 第一轮（10-26）：分页等宽 ＋ 通话键钉底

用户两张截图：
> 「现在标签页的长度不均匀，应该一样长度，字显示不全没关系。」
> 「电话界面，无论是『听下句』还是选项，都应该贴在界面最底部锁定，不要跟着上面的对话栏长度来回变，你看看我的建议是否合理，合理就改，不合理就算了」

### 一、分页等宽

原来每格宽度跟着标题长短在 170–230px 之间伸缩（`min-width: 170px; max-width: 230px`），
四格排出来长短不齐，像撕坏的纸条；`廿八屋 - 香港租盘` 刚好 170，`维港大学 - 维基百科，自由的百科全书`
顶到 230。真浏览器（IE8／IE9 也一样）的分页是等宽的，写不下的标题一律截断加省略号。

改动（`style-chrome.css`）：

```css
.browser-tabs { --tab-w: 198px; }
.browser-tabs button { width: var(--tab-w); flex: 0 0 var(--tab-w); max-width: none; }
.browser-tabs .tab-cell { flex: 0 0 var(--tab-w); width: var(--tab-w); }
@media (max-width: 800px) { .browser-tabs { --tab-w: 142px; } }
```

- `tab-cell`（带 × 的那层）也跟着定量，否则按钮等宽了、外框还在按内容撑。
- 原来 ≤800px 那条 `.browser-tabs button { min-width: 0; flex: 1 }` 会让分页挤成均分的窄条，
  改成直接换档 `--tab-w`，宽窄两边同一套逻辑。
- 「不缩格、不换行、整排横向推」的原设计没变：装不下就滚（`scrollWidth 593 / clientWidth 347`，360 宽时）。
- `style-base.css` 里那份兜底规则同步（160px），注释改掉「170–230px」。

实测：1080 四格 198／800 四格 142（都 `same: true`）；360 宽 142 一格、整排可横推；
只有维基那条长标题 `clipped: true`（省略号），其余三条完整。

### 二、通话键钉底

原来是「对白块多高，按键就跟到多高」：`.phone-script { flex: 0 1 auto; max-height: 42% }`
自己按内容伸缩，按键紧接在它下面，`.phone-fakekeys` 用 `margin-top: auto` 单独顶底。
于是每换一句台词，「听下句」就上下跳一次；选项那屏更明显——一句话短，三颗选项就飘到屏幕中间，
和上面那句「听筒里静了半拍」之间空出 226px。

判断：**合理**。真手机的通话界面按键是固定的，动的只有字。但只把按键顶底还不够——
空档会从按键下面搬到对白和按键中间，反而把「提示语→选项」这一对拆散了
（试过这一版，`_tb_phone3.png` 里「听筒里静了半拍」和它下面三个选项隔着 226px）。
所以让**对白块自己吃掉上方的空档**：对白贴着按键往上长，空白留在头像底下，
真手机的通话界面本来也是这块空。

```css
.phone-script { margin: auto 0 12px; }      /* 原 margin: 8px 0 12px */
.phone-choices, .phone-pad { margin-top: 0; }  /* 原来没有，靠 script 推 */
.phone-fakekeys { margin-top: 0; }          /* 原 margin-top: auto */
```

- 三颗选项高、一句短话矮，`keyBottom` 都不动；对白与按键之间恒为 12px。
- `phone-ops`（「拨给阿明」那排通讯录键）走同一个槽位，也自动跟着到了底部，不用另写。

实测（`keyBottom` 为按键底边到手机框顶的距离）：

| 屏 | 短句 | 长句 | 选项 |
| --- | --- | --- | --- |
| 720×900 | 635 | 635 | 635 |
| 720×620 | 447 | 447 | 447 |
| 360×720 | 533 | 533 | 533 |

三档都 `incallScroll: false`（不用滚）、`docOverflow: false`（不出横向滚动）、`scriptGap: 12`。

## 第二轮（10-27）：廿八屋发帖，必须自己按「发布」

用户：
> 「廿八屋的发帖需要每次让玩自己点击发出，完成后才能通关，不能莫名其妙多了章慧琪发出的帖子。」

### 根因：`ensureSerials()` 替玩家发帖

`setTime()` 每推进一次时钟都会调 `ensureSerials()`（`core.js:417`），原来它是这么写的：

```js
SERIAL_DUE.forEach((d) => {
  const when = serialWhen(d.id);
  if (flag(d.key)) { …pinSerial…; return; }
  if (!d.ready() || now < when) return;
  pinSerial(d.id);
  flag(d.key, true);        // ← 钟点一到就替她发出去
});
```

而 `ready` 是 `hasEvidence("paper-16") || S.level >= 8` 这种条件。于是第 7／9／11 关里，
只要时钟过了帖子标注的刊登时间（08-17 09:00 之类），玩家还站在房间里没碰过电脑，
「阿琪V」的连载帖就已经挂进了讨论区，「发第一帖／第二帖／第三帖」三条必做也自己勾上——
三关都能不发帖直接按「往下」过关。玩家看到的是：我什么都没按，怎么多了一篇她的帖。

原本那条注释担心的是「回复时间被推到还没到的钟」，但这件事 `pinSerial()` 早就解决了：
它把 `S.postAt[id]` 钉在剧本那一点（`serialWhen`），跟玩家哪一刻按发布无关。
自动置 flag 是多余的，而且正好把「发帖」这个动作抹掉了。

### 改动

`web-ui.js` — `ensureSerials()` 只补钉子，不发帖：

```js
function ensureSerials() {
  if (!S || !S.flags) return;
  SERIAL_DUE.forEach((d) => {
    if (!flag(d.key)) return;                 // 没发过就什么都不做
    const when = serialWhen(d.id);
    if (!S.postAt || S.postAt[d.id] !== when) pinSerial(d.id);
  });
}
```

`web-data.js` — `SERIAL_DUE` 去掉 `ready` 字段（它的唯一用途就是自动补发）：

```js
const SERIAL_DUE = [
  { id: "wk1", key: "serial1" },
  { id: "wk2", key: "serial2" },
  { id: "wk3", key: "serial3" },
];
```

现在 `serial1/2/3` 只有一处能置位：`publishSerial()`（草稿页那颗「发布」按钮）。
其余关卡侧一律只读。

### 为什么这样就「不发不通关」

- 三条「发第 N 帖」都是 `need: true`，`levelReady()` 要求所有必做 `done()`；`serialN` 不置位就不放行。
- 草稿页是 `S.pendingPost` 撑起来的：只要它还挂着，`holdForPost()` 会把任何导航拽回 `/post`，
  `closeRental()` 关网页也会弹「先按『发布』，关掉窗口不会把帖发出去」。
- 便条上一直写着「看完草稿，按下面的『发布』。不按就不算发出去。」

### 实测（CDP，`?level=7/9/11`）

| 关 | 时钟推到 | 发帖前 | 点「发布」后 |
| --- | --- | --- | --- |
| 7 | 08-22 21:00 | `serial1` 空、帖子不在列表、`levelReady()` false | true，列表有帖，刊登钉回 `08-17 09:00` |
| 9 | 08-29 21:00 | `serial2` 空、`levelReady()` false | — |
| 11 | 09-05 21:00 | `serial3` 空、`levelReady()` false | — |

缓存号：`web-data.js=20261027-post1`、`web-ui.js=20261027-post1`。

# 第三轮：全站网页五类问题复查

按「设计不符常理／交互逻辑混乱／内容太假或冗余／提前剧透穿帮／AI 味重」五把尺子过了一遍
廿八屋、墙簿、通搜、维基、香港日报、维大官网、VHU Portal、广告落地页。改了九处。

## 一、交互逻辑混乱（三处）

### 1. 求助帖的门槛形同虚设

`web-ui.js` 原代码：

```js
function helpRepliesOpen() {
  return (S.helpSearches || 0) >= 3 || noted("bbs-self");
}
function countViewTry() {
  if (helpRepliesOpen()) return;
  S.helpSearches = (S.helpSearches || 0) + 1;
}
```

问题不在门槛数值，在**计数的单位**：`countViewTry()` 在「预约睇楼」按钮里调用，
而按钮带的是「这一次点击」、不是「哪一间」。于是**同一间连点三次**就放出藤先生的回覆——
她只碰过一间盘，帖子就有人回了，与日记簿「一间一间对过去」的玩法直接冲突。

改成按盘计数：

```js
function viewTriedCount() { return Object.keys(S.viewTried || {}).length; }
function helpRepliesOpen() {
  // S.helpSearches 是旧档留下的计数，只读不再写——跳关补前情那条路径还在用它。
  return viewTriedCount() >= 3 || (S.helpSearches || 0) >= 3 || noted("bbs-self");
}
function countViewTry(id) {
  if (helpRepliesOpen() || !id) return;
  S.viewTried = S.viewTried || {};
  S.viewTried[id] = true;
}
```

四处调用点全部补上 `l.id`。`levels.js` 第 1 关 `gives()` 里的 `S.helpSearches = 3`
换成 `S.viewTried = { tk: true, tw: true, wc: true }`。
`S.helpSearches` 字段留着只读，是为了旧存档不丢——**旧档里已经 3 的人照旧开着**。

### 2. 通搜「热门」点了必然找不到

`seHit()` 只认「维港／維港／vhu」，而首页热门第二条是「深水埗　重建」——
点了回一句「找不到符合的结果」。**热门推荐点不到东西，等于在骗人点。**

改成按词分组（`seResultsFor(q)`），深水埗那组给两份真结果：

- 市建局资料页 → `vhuOpenUrl()` 进 `web-error`，地址栏留着
  `www.ura.org.hk/tc/projects/sham-shui-po`。**这是钩子**：她拿不到内容，只拿到一串路径。
- 香港日报 8/21「旧楼重建与健康」→ `hknews`。

摘要里**不写「持续研究」四字**——那是第 2 关的答案，写在这儿就把那关说穿了。
市建局那条只写「本局正就区内楼宇状况收集资料，范围及时间表待定」。

### 3. 维基搜索框是半功能

`wikiHead()` 的 `wk-q` 只有 `input`、没有 handler，字打得进去，按「搜索」毫无反应。
按既有判据「半功能比死链更假」，要么删要么接。选了接：

- 认得的词（维港／維港／vhu）→ 留在条目，什么也不变；
- 不认得的词 → 页面最顶加一块 `.wk-noresult`，照二〇一四年那句回
  「维基百科目前没有名为「X」的条目。」，末尾点明「下面仍是『维港大学』这一条」。

**位置踩过一次**：第一版放在 `h1` 上方、标签之下，读起来像「维港大学是一个不存在的条目」。
现在压在「条目／讨论」那排标签**之上**，是页面内容区第一块。

## 二、AI 味重（三处）

### 4. `LISTINGS` 二十条 `sub` 同一个节奏

二十条全是「特点＋条件＋日期」三顿号，并列一眼就是模板。逐条重写，长短参差、
业主自让的偏口述、代理代放的偏条款。**代价要留意**：`listingBlob()` 用 `sub` 参与搜索，
`listingIsShare()` / `listingIsEstate()` 用正则匹配 `sub`——
「合租／分租／雅房／板间／分住」「屋苑／新邨／第一城／花园」这些词一个都不能动。

### 5. 代理回覆一个腔

十四条 `failBody` 原本都是「请先提供 X，再安排睇楼。本盘不接受周租。」
改短、改散（最短的一条只剩「只租日间上班族。公司证明带来再说。」）。

**但每条必须保留原来会触发的四道门槛关键词**（`FOUR` 的 `hit` 正则：
粮单／担保／即日·一年·订金／周租·按周·口头·家庭户），
否则日记簿「卡住：某盘」就对不上了。改完逐条核过命中集合没变。

`failTitle` 顺带去掉句号：全站 `showPrompt` 的标题都没有标点，只有这一批带了。

### 6. 「最近搜过」用全角空格和斜线拼成一条长串

`WEB_STR.recentSearch` 原值：
`"最近搜过：元朗　天水围／荃湾　新楼／大角咀　套房"` —— 三笔搜寻拼一行，只有机器看得顺。

拆成三块可点的浅底方框（`.recent-searches` / `.recent-q`），点一下重搜。
**加边框不是为了好看**：词里本来就有空格（「元朗 天水围」），不加边就分不清哪几个字是一组，
截图上会读成「元朗 天水围 荃湾 新楼 大角咀 套房」六个词。

## 三、太假／冗余（三处）

### 7. 首页两条通知正文一字不差，其中一条在撒谎

```js
if (postedHelp() && helpRepliesOpen() && !noted("bbs-self")) { …「有新回复」… }
else if (postedHelp() && !flag("sawOwnPost")) { …「有新回复」… }   // ← 同一句
```

底下那条更糟：藤先生**还没回**，也说「有新回复」，她点进去看见自己那帖底下空着。
**提示在替网站撒谎。** 没人回就写没人回——改成「你的帖子还在，暂时没有人回。」

### 8. 墙面广告按钮跟弹窗互相打脸

四个小商户页（手机铺／搬屋／补习／迷你仓）的 CTA 叫「亲临门市」「致电查询」，
按下去弹「本页不收预约」「本页不拨号」。**钮说要人做的事，弹窗说做不了。**

四个页面的 `cta`／`ctaFail` 全删，`viewAdShop()` 改成 `a.cta ? … : ""` 不渲染按钮区。
二〇一四年信和二楼那种铺头本来就只在网页上留个电话，没有按钮。
**保险那一页留着表单和「提交查询」**：表单是真有的，交不上去也是真的
（`ctaFail` 改成「送出时连不上伺服器。请于办公时间致电 3188-0628。」，
弹窗标题从「未能完成」改成「提交失败」——没有网站会说「未能完成」）。

### 9. 租务须知像法例转载

- 印花税那条砍掉「查询可向税务局印花税署」等；
- 「市场常见为两个月按金加一个月上期」删掉——首页侧栏 `tip2` 讲的就是这件事，
  同一页里讲两遍，只剩一遍的分量；
- 「个案情况请自行向律师查询」删掉——页脚每页都有「成交前建议咨询律师」。

**第 4 条「出租范围与屋内物件」一个字没动**：储物室那句是第 2 关的伏笔。

## 四、顺手修的两处

- **图书馆逾期日数不写死。** `VHU_BOOKS` 第三册原本 `over: "3,579 日"`（按 9-07 算死的），
  她 9 月 3 日打开也是这个数。改成 `bookOverDays(due)` 按 `clockDate()` 现算。
  日记簿那条 note 里的「逾期三千五百七十九日」也删了——日期是线索本体，天数只是系统顺手算的。
- **通搜首页地址栏不该带 `?q=`。** 未搜索时页面是首页，地址栏却像刚搜过。
  `webAddr()` 的 `engine` 改成按 `S.seSearched` 分岔。

## 五、核过但**没改**的

- **「·」全站正文零使用**，唯一一处在 `vhuAnsNorm()` 的正则字符集里，是用来剥掉中点再做答案比对的。
  「滥用中点」这条不成立。
- `NEWS` 那八条无钩子的港闻（运头塘村／天文台／港铁／食物安全…）：**这是生活底色，改了反而假**。
- `VHU_NOTICES_OLD` 只放一条 2004 年存档、维基侧栏几十个 `wk-dead`、官网导航「研究／校友／捐赠」
  死字：旧站栏目没建完就是常态，全做成真的反而假。
- 墙簿「最近：廿八屋　深水埗 唐楼」的全角空格：那是字段分隔（在哪看过什么），
  不是列表拼接，读起来正常。

`style-chrome` / `style-vhu` 七个）。

# 第四轮（10-28）：墙簿个人主页的照片墙

用户的原话：「墙簿个人主页的照片墙 UI 应该也是绿色的，和墙簿一致，并且边框、边距要正常不要重叠。」

截图里那一页只有顶上一条绿：页头是 `#6c956f→#4f7657` 的绿带，往下到照片墙就成了灰白 ——
照片直接铺在 `#f4f6f1` 上，一圈 1px `#c9d2c6` 细边，跟墙簿这个站没有关系。

## 一、边框为什么「重叠」

不是视觉错觉，是盒子算错：`.wall-shot{width:148px; border:1px}` 内容盒只有 146，
而里面 `.img-slot.wall-thumb` 写死 `width:148px` —— 图片比它的相框宽 1.7px，压出右边框。
同时 `.img-slot` 自带一层 1px `#b9b9b9`，两层线错着贴在一起，放大看是两条不同粗细的边。

改法：

| 改 | 原来 | 现在 |
| --- | --- | --- |
| `.wall-shot` | `width:148`（content-box） | `box-sizing:border-box` + `width:156`（相纸含白边） |
| `.wall-album .wall-shot .img-slot` | `width:148px` 死值 | `width:100%`，跟着相纸内框走 |
| `.img-slot` 自带边框 | 留着 | 相册里 `border:0`（4px 白边已经是框） |
| `.wall-shots` 间距 | `gap:8px` | `gap:10px`（白边进来后 8px 显挤） |

实测：相纸 156 → 内容 146.7 → `img-slot` 146.7 → `img` 146.7×110，四层同宽，零溢出。

## 二、怎么让它「绿」

不是把照片染绿，而是把照片**贴在绿色相册板上**：

- `.wall-album`：浅绿板 `#e3eedd` ＋ 1px `#a8c0a3` 边；相册名做成一条绿带
  （与站头同一支 `linear-gradient(#6c956f,#4f7657)`、白字），负 margin 顶到板的两边。
- `.wall-shot`：白相纸，4px 白边托住照片，外面一圈 1px `#a9bfa5`；hover 边框转深绿 `#4f7657`。
- `.wall-album-name` 本身仍是绿色小字 —— 「動態」也用这个类但不在相册里，不能跟着长绿带。

**板宽用 `fit-content`，不用整宽。** 先按整宽做过一版：两块板各 974，而「相册「生日」」只有
一张照片，右边空出 600px 的绿 —— 比没有底色更难看。收紧后板跟着照片走，像两本相册叠着。

## 三、一个自己挖的坑：百分比宽度 + fit-content

窄屏（≤640）为了让三张照片不必滚三屏，改成 `width:calc(50% - 5px)` 一行两张。
但板是 `fit-content` —— **百分比没有确定基准**，浏览器一路收到最小，两张缩成 80px 的指甲盖。
窄屏必须把板放回 `width:100%`，百分比才有得算。

## 四、顺手修的：帖子配图

`.post` 里的配图（`wallPost(..., {photo})`）用的是同一个 `.wall-shot`，同样 content-box
＋ 内层 148 死宽，同样压边。一并改成 border-box ＋ `width:100%`，外观不变（还是 148 宽、无白边）。
