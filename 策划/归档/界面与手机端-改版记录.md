## 一、怎么量才算量过

不靠看截图说「还行」。每屏跑一个审计函数，遍历 `#app *`，四条判据：

| 判据 | 表达式 | 说明 |
| --- | --- | --- |
| 横向溢出 | `right > vw + 1.5 \|\| left < -1.5` | 顺带看 `docW > vw`，防整页能左右拖 |
| 点击区过小 | `button/a/input/[role=button]/.tap` 且 `w<32 或 h<32` | 手机上嫌 32 都小，40 才舒服 |
| 字号过小 | 叶子节点文本 `< 11px` | |
| 被底栏压住 | `bottom > pbTop + 2 && top < pbTop` | 只对**不滚动的**容器成立，滚动容器要先滚到底再量 |

三个坑，都踩过：

1. **探针必须 `Network.setCacheDisabled({cacheDisabled:true})`。** 第一轮改完重跑，数字一模一样，
   以为 CSS 没生效——其实是浏览器吃了旧 `style-chrome.css`。`?v=` 换了也没用，同一 profile 的 HTTP 缓存还在。
2. **`Runtime.evaluate` 的返回层级取决于 cdp 封装。** 返回整条消息时是 `r.result.result.value`，
   封装成只回 `m.result` 时是 `r.result.value`。写深一层就是一路 `undefined`，看着像「页面没加载」。
3. **中文路径要 `encodeURI()`，不要手打百分号编码。** 手打成 `%E9%81%8A%E6%88%B2`（繁体的「遊戲」）
   服务器直接 404，页面 `title` 变成 `Error response`，脚本里看到的是「元素全都不存在」。

## 二、量出来五处硬伤

### 1. 底栏三个换屏按钮只有 25px 高

手机上换屏只有「瀏覽器／日記簿／地圖」这一条路，量到 `72×25`。手指按得进去但按不准。

```css
@media (max-width: 720px) { .playbar-mid button { padding: 12px 0; } }
```

`72×25 → 72×41`，底栏整条 `64 → 76` 高。桌面（1280）不动：仍是 `248×25`、底栏 `1280×64`。

### 2. 过场「跳过」贴死右下角

`49×23`，`right:18px bottom:14px`，色 `rgba(232,220,198,.5)`——在照片上看不见，也够不着。

```css
@media (max-width: 640px), (pointer: coarse) {
  .cut-skip { right: 8px; bottom: 8px; padding: 12px 16px; font-size: 13px; }
}
```

`49×23 → 63×40`，离两边各 8px。用 `pointer: coarse` 而不是只看宽度：触屏的 13 寸平板也算手。

### 3. 顶栏四个开关 30px

`.os-opt`／`#sfx-toggle`／浏览器导航／`#map-close` 一起给 `min-height: 34px`，
`#os-bar` 的 `padding: 0 4px; gap: 6px` 把横向留白收紧。改后 `48×34`／`68×34`。

### 4. 390 宽时日期被截成「2014年7月31日 周…」

顶栏左边那格应用名 `#os-title` 占 36px，日期就少 36px。时间（`23:14`）整段看不见了。

```css
@media (max-width: 480px) { #os-title { display: none; } #os-bar { padding-left: 8px; } }
```

改后 390 与 360 都是全文：`2014年7月31日 周四 23:14`，`clientWidth 126 == scrollWidth 126`。
`#os-title` 是那格「瀏覽器／日記簿」的应用名，本来就在底栏写着，手机上去掉不丢信息。

到 320 也放得下：日期 `86`、`自動× 48`／`粵語 32`／`字 中 38`／`環境音 大 68`，最右到 `316`，
`#os-bar` 320 宽还剩 4px。所以不必再给 320 做第二档降级。
（判字有没有被切，别用眼睛看截图里的框——量 `scrollWidth > clientWidth + 1`；
`text-overflow: ellipsis` 的容器 `scrollWidth` 不出溢，还要看 `textContent` 有没有被截在半个字上。）

### 5. 地图弹层把详情挤成 164px，还得在小框里再滚一层

竖屏下平面图与详情上下排，详情拿到 `clientHeight 163 / scrollHeight 291`；
滚到底时照片下沿 877 已经越过弹层下沿 762 —— 两层滚动套在一起，手指一动就分不清滚的是哪一层。

```css
@media (max-width: 800px) {
  #map-layer { padding: 8px; }
  #map-sheet { max-height: 100%; }
  #map-main { display: block; overflow-y: auto; overscroll-behavior: contain; }
  #map-draw { min-height: 0; }
  #map-detail { overflow: visible; border-left: 0; border-top: 1px solid #d7ccb8; }
}
```

改成整块单轴滚动（平面图跟着一起走），详情不再自己滚、左边框换成上边框表示「在下面」。
改后一张截图里平面图＋房间名＋说明＋整张照片一次可见。

## 三、附带两处

**`.chat` 两个高度用 `100dvh`。** 手机浏览器的 `100vh` 是「地址栏已经隐藏」那个高度，
比屏幕上真看得见的高出约 60–120px，窗口底（输入框）会被切掉。

```css
height: min(680px, calc(100dvh - 88px));   /* 桌面那档保留 100vh 也行，dvh 更准 */
height: calc(100dvh - 56px);               /* 手机那档 */
```

**窄屏地址栏折行，「轉到」掉到第二行左端孤零零一颗。** 原来 `.browser-chrome` 是 `flex-wrap: wrap`，
390 时地址栏占满一行，按钮被挤下去。

```css
@media (max-width: 800px) {
  .browser-chrome { flex-wrap: nowrap; }
  .addr { flex: 1 1 0; min-width: 0; }
}
```

改后 390 与 320 都是单行：`.addr 160..331`、`.go-btn 336..380`。

## 五、判为「不是缺陷」的五处

体检会一直报它们，逐条记下理由，免得下一个人再去改一遍：

| 报的什么 | 为什么不改 |
| --- | --- |
| `.browser-tabs button` 溢出（`x307..449`） | 分页刻意见等宽横向推、滚动条收起（2014 年 IE 的样子），CSS 注释已写明 |
| 廿八屋站内 `.web-link` 22×27、页脚 10px | 站内是「2014 年的真网站」，页脚密排是刻意还原；玩家不靠它翻页 |
| `#clock` 10.5px | 原来是被截断才显得坏，现在全文可见，字号是设计（顶栏就那一行位置） |
| `?test` 列表 `.test-list a` 39×28 | 开发者页，不是玩家入口 |
| `caption-plate` / `cut-plate` 的 `img` 溢出 3–9px | `push:true` 是 1→1.08 倍推镜，父容器 `overflow:hidden` 裁掉，不算溢出 |

另有一条**看着像缺陷、其实是误报**：网页页脚被底栏压住（第一轮报 7 处）。
`.hk-site` 自身就是滚动容器（`ch554 sh782 ov auto`），滚到底后 `footerBottom 708 < pbTop 768`。
审计函数只对不滚动的容器判遮挡，所以这条后来不报了——量遮挡之前先确认那个容器会不会滚。
