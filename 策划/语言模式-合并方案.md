# 语言模式合并方案

> 2026-10-30。起因：粤＋普模式下「网页、长文、簿子、旁白」全是粤语港繁，
> 与普通话模式重叠太多，三个按钮的差别记不住。本文只谈「怎么改」，改完再回写
> `策划/文字规范.md` 第 1 节。

## 0 一句话

**合并的实质不是删一个按钮，是把「粤＋普」的正文语言从粤语换成普通话；人物对白仍是
「粤语主行 ＋ 普通话小字」。** 技术上只需要改 6 处判断、拆一条对白通道、补 3 条对照表——
**不需要重新翻译**，因为 `zh` 模式已经跑在同一套 `zhOf()` 表上，翻译早就齐了。

---

## 1 现状：三档到底是什么（实测，不是推测）

在 `?level=6`、`langMode = "both"` 下取 `#stage` 的 `innerText`，再在页面里把
`H()`／`T()` 换成普通话版本重绘，得到同一屏的两份文本。差别只在这几处：

| | 粤语 | 粤＋普（现状） | 普通话 |
| --- | --- | --- | --- |
| 顶栏 | 港繁 | **港繁** | 简体 |
| 网页（廿八屋） | 港繁粤语：租盤／業主自讓／兩按一上／你可能想睇 | **同左** | 简体普通话：租房／房东直租／押二付一／你可能想看 |
| 日记簿、证物、卡片 | 港繁 | **港繁** | 简体 |
| 旁白（`line("", …)`） | 港繁 | **港繁** | 简体 |
| 角色对白（有 `who`） | 港繁粤语，单行 | 港繁粤语 ＋ 下面一行普通话小字 | 简体普通话，单行 |
| 选项按钮 | 港繁 | **港繁** | 简体（夹粤语的 3 条会漏） |

所以现在「粤＋普」和「普通话」的差别有**两件事**：正文语言（粤 vs 普）、对白行数（双 vs 单）。
两件事挤在一个按钮里，玩家记不住，作者自己也要试才知道。

### 1.1 一个实测结论：翻译是齐的

把 `H()`／`T()` 在 both 下强制走普通话，网页整页从
「租盤／業主自讓／兩按一上／討論區」变成「租房／房东直租／押二付一／论坛」，
**没有一处漏出粤语**（`_p2_web_both.png` / `_p2_web_after.png`）。
这证明合并的翻译成本≈0：`zh` 模式就是这么跑的。

## 2 合并的实质：把「粤＋普」从 (粤,是) 挪到 (普,是)

三档其实是「正文语言 × 对白是否加对照」的三种组合：

| 组合 | 正文 | 对白对照 | 现在是 |
| --- | --- | --- | --- |
| (粤, 否) | 粤语 | 无 | 粤语 |
| (粤, 是) | 粤语 | 有 | **粤＋普（现状）** |
| (普, 否) | 普通话 | 无 | 普通话 |
| (普, 是) | 普通话 | 有 | **空缺** |

合并＝把「粤＋普」挪到空缺那一格。挪过去之后：

- **粤语**：全站港繁粤语，对白单行。
- **粤＋普**：正文／界面／网页／簿子／聊天＝简体普通话；**角色对白＝港繁粤语主行 ＋ 简体普通话小字**；旁白＝简体普通话单行。
- **普通话**：全简体，对白单行。

留下的空缺是 (粤, 是)——「全站港繁 ＋ 对白加普通话小字」。这一格没人需要：正文本来就是
粤语书面语，懂粤语的人不需要小字，不懂的人也不会选粤语模式。**所以挪过去不丢组合，只丢顺序。**

### 2.1 判据（写进规范，以后新增文本照这条走）

> **她「听到的」用粤语；她「看到的」「想到的」用普通话。**

- 听到的：角色对白、电话、语音留言、隔门听。
- 看到的：网页、新闻、日记簿、证物、卡片、地图、聊天记录（她在读字）。
- 想到的：旁白、选项提示。

这条判据同时解释了为什么聊天不加双行：聊天是**她低头读的**，不是她听见的。

## 3 三种落法，选一个

| | 做法 | 代价 | 改动量 |
| --- | --- | --- | --- |
| **A（推荐）** | 保留三档，只把「粤＋普」的正文语言改成普通话 | 无功能损失；「粤＋普」不再是全港繁 | 6 处判断 + 1 处对白通道 |
| B | 在 A 之上删掉「普通话」档，只剩两档 | 只想要一行普通话的玩家没有选择；localStorage 老值要迁移 | A ＋ 迁移 ＋ 文案 |
| C | 不合并，只把 both 的「非对白」改普通话，三档语义更清楚 | 与 A 完全相同 | 同 A |

**推荐 A。** 理由：

1. 用户要解决的是「粤＋普里其他部分还是粤语，太绕」，A 直接解决，且一个组合都不丢。
2. 「普通话」档不是冗余：有玩家一行粤语都不想看。A 之下它的行为不变，等于白留。
3. 删档要迁移本地存档（`undo-lang-v3` 存的是字符串，老值 `"both"` 删掉后 `LANG_MODES.includes` 为假 → 回退粤语，原本选粤＋普的人升级后突然全粤语）。风险大于收益。
4. A 上线跑一阵，若确实觉得三个按钮多，再做 B——**B 是 A 的删减，不是另一套实现**。

下文按 A 写。B 的增量在 §7。

## 4 详细改动（A）

### 4.1 `core.js`：3 处判断，让 both 跟普通话走

```js
// 55—56 行
const LANG_MODES = ["yue", "zh", "both"];
const LANG_LABEL = { both: "粤＋普", yue: "粤语", zh: "普通话" };
```
改成（顺序按「辅助递减」排，点一下从全粤语到有对照，再点一下到纯普）：

```js
const LANG_MODES = ["yue", "both", "zh"];
const LANG_LABEL = { both: "普＋粤", yue: "粤语", zh: "普通话" };
```

三处 `mode === "zh"` 改成 `mode !== "yue"`：

| 行 | 函数 | 现在 | 改成 |
| --- | --- | --- | --- |
| 88 | `T()` | `if (mode === "zh") return z;` | `if (mode !== "yue") return z;` |
| 104 | `H()` | `if (mode === "zh") return zhOf(...)` | `if (mode !== "yue") return zhOf(...)` |
| 127 | `Tblock()` | `mode === "zh" ? (z \|\| raw) : y` | `mode !== "yue" ? (z \|\| raw) : y` |

`Ts()`／`Ty()` 走 `T()`，自动跟随。

`cycleLang()` 的提示语（176—182 行）改一句，切到「普＋粤」时说明它到底是什么：

```js
if (langMode === "both" && typeof showPrompt === "function") {
  showPrompt(H("普＋粤"),
    H("网页、日记簿、长文用普通话。人物对白仍是粤语原句，下面一行普通话小字。"));
}
```

> 注意 `H()` 在 both 下已经是普通话，这里**不能再包 `toHkTrad`**，否则提示语自己变港繁。

### 4.2 `talk.js`：拆开「对白通道」与「界面通道」（本方案唯一的技术难点）

现状 `yueFace(s) = H(s)`，被两种用途共用：

- **对白**（`faceLine` 里的 1 处）：both 下需要港繁粤语。
- **界面词**（其余 17 处：挂断／静音／听下句／你说／短讯……）：both 下应当跟普通话走。

`H()` 一旦在 both 下变普通话，`faceLine` 就会把对白也翻译掉——**双轨变成两行普通话**。
所以必须把这一处拆出来：

```js
// talk.js 115 行后新增：只做港繁，不读 langMode。对白专用。
function faceYue(s) {
  const t = String(s == null ? "" : s);
  return typeof toHkTrad === "function" ? toHkTrad(t) : t;
}

// 120—127 行
function faceLine(text, zh, narr) {
  const mode = typeof langMode === "string" ? langMode : "both";
  if (mode === "zh") {
    const z = zh != null && zh !== "" ? String(zh) : String(text || "");
    return z.trim().replace(/^[（(](.*)[）)]$/, "$1");
  }
  // both 下的旁白：源码本来就是简体书面语，原样出就是普通话
  if (mode === "both" && narr) return String(text || "");
  return faceYue(text || "");
}
```

两处调用补 `true`（旁白）：

- `drawFace` 的 stageDir 分支（565—570 行）：`faceLine(prompt, b.zh || b.promptZh, true)`
- `drawPhone` 的 narr 分支（595—606 行）：`faceLine(b.choices ? b.prompt : (b.text || ""), b.zh || b.promptZh, true)`

**不用改的**：

- `talkBody()` 的 `showZh`：`mode === "both"` 不变。它只用于角色话（stageDir 分支不走它），
  both 下第一行仍是 `faceLine` 出的港繁粤语，第二行 `z` 是普通话小字。
- `choiceBox`／手机按钮里的 `yueFace`：保留。它们 now 走 `H()`，both 下自动变简体普通话，
  这正是「界面用普通话」。**只把 `choiceBox` 的 `yueFace(c.label)` 想清楚**：label 是普通话书面语
  （85 条里只有 3 条夹粤语：见 §4.4），走 `H()` 后 both/zh 都是简体，yue 仍港繁，行为正确。

### 4.3 `story-late.js`：过场字幕（单行，没有第二轨位置）

```js
// 1321—1322 行
const main = mode === "zh" ? zh : toHkTrad(yue);
// →
const main = mode !== "yue" ? zh : (typeof toHkTrad === "function" ? toHkTrad(yue) : yue);
```

`teaserSay()` 只有陈家豪一句「第二章预告」类字幕，无双行位置，both 下取普通话即可。

### 4.4 数据：补 3 条选项的普通话

`choiceBox` 的 label 走 `H()`，both 下查 `yue-zh.js`。85 条 label 里夹粤语词的是：

| 文件 | 现在 | 建议表里加 |
| --- | --- | --- |
| `story-early.js` | 我今晚返去。你当我又讲大话。 | 我今晚回去。你当我又说大话。 |
| `story-clinic.js` | 我怕我一说，你心入面就有数。 | 我怕我一说，你心里就有数。 |
| `story-clinic.js` | 我讲得慢，你等得就等。 | 我讲得慢，你等得了就等。 |

加进 `游戏/assets/yue-zh.js` 的 `YUE_ZH`，键是源码原文（简体、港繁前），值是普通话。
加完跑 `verify_table.py` 与死条目检查。**不需要新增 `labelZh` 字段，也不改 `choiceBox` 结构。**

### 4.5 不需要改的地方（已确认）

| 载体 | 通道 | 为什么自动生效 |
| --- | --- | --- |
| 网页／新闻／讨论区／盘源 | `T()`／`Ty()`／`W()` | 双轨已齐，三处判断改完自动取普通话 |
| 日记簿／证物／卡片／任务 | `el()` → `H()` | 同上 |
| 地图、hub 便条 | `el()` → `H()` | 同上 |

| 图片配字／`alt` | `H()` | 同上（图上的字不能改，见 §6.3） |

**注释要跟着改**（它们现在写着「粤＋普转港繁」，改完就错了）：
`core.js:11`、`core.js:97`、`talk.js:119`、`talk.js:303`、`web-vhu.js:1018`。
其中 `web-vhu.js` 那句说的是「粤＋普界面是港繁，有人会照屏幕上的字打繁体」——
合并后 both 界面是简体，那句要改成「只有粤语模式是港繁」，`vhuAnsNorm` 的

## 5 观感：合并后一屏里会出现三种字

这是本方案最需要作者拍板的一点，先把事实摆出来（`_p3_talk_after.png`）：

```
周                                     ← 名字：简体
行上嚟好熱吖嘛？飲杯水，唔燙嘅。        ← 主行：港繁粤语（18px，橙黄）
爬上来热吧？喝杯水，不烫。              ← 小字：简体普通话（小一号，暗橙）
```

**同一屏：旁白简体／名字简体／对白主行港繁／对白小字简体。** 这是「听到粤语、看到普通话」
的直接结果，不是 bug。但它是一个明确的风格选择，所以要写在这里：

- 若接受：合并后的 both 就是「**字幕版港片**」——画面与叙述是普通话，人物开口是粤语原声。
- 若不接受（觉得繁简同屏割裂），唯一解法是把对白也全部转简体（`faceYue` 改成不做港繁），
  代价是粤语只剩用词、没了字形，且 `toHkTrad` 的词组映射（的士／巴士）也不会生效。

**推荐接受。** 对白主行是港繁，正好把「这是原话」标出来；旁白是简体，读起来轻。
两者在同一屏不打架，因为字号、颜色、位置都不同（`_p3_talk_after.png` 已确认）。

## 6 风险清单（按严重度）

### 6.1 致命但易发现：`yueFace` 没拆干净

`faceLine` 若仍走 `yueFace`（=H），合并后对白会变成「普通话主行 + 普通话小字」两行重复。
**自检办法**：切到「普＋粤」，看一句对白——第二行必须与第一行**不同**，且第一行有「唔／嘅／咗」。
`tools/冒烟.cjs` 抓不到这一类（它不比对两行是否相同），必须人眼或新脚本验。

### 6.2 选项夹粤语（3 条，已列 §4.4）

不补表，both 下这 3 个按钮会显示「我今晚返去。你当我又讲大话。」——简体字、粤语词，
比港繁更怪（看着像错字）。补表即可。

### 6.3 图上的字不会跟着变

烧在图里的汉字（卡片背景、毕业照钢笔字、日历页、公告类）在 both 下仍是**繁体**，
而周围 UI 已经是简体。这是**合并新增的观感问题**（现状 both 全港繁，图字与 UI 一致；
zh 模式本来就有这个问题，只是选的人少）。

处理建议（按性价比排序）：

1. **先清点**：把 `图/游戏/README.md` 里「图上有可读汉字」的条目列出来（按图注逐条过，
   不凭印象估数），逐张判断「这张会不会被读到」。
2. 会读到的（如毕业照右下角钢笔字、卡片上的手写行），**改写图**或**改写正文**（让玩家从
   正文拿到那条信息，图只作氛围）——后者便宜，符合「图跟正文对得上」的既有规矩。
3. 纯粹氛围的（招牌、报纸版面），不处理。

### 6.4 顶栏按钮变宽

`LANG_LABEL.both` 从「粤＋普」改成「普＋粤」，**字符数相同**，顶栏宽度不变。
若改成「普通话」会与 zh 档重名且多一个字，390 下会挤——不要用。

### 6.5 `zhOf()` 漏译会被更多人看到

合并前只有选「普通话」的人遇到漏译；合并后「普＋粤」也走同一条路（用户基数更大）。
但**不是新增风险**：漏的条目在 zh 模式下早就漏了。建议顺手加一个扫描脚本（§7.2）。

### 6.6 老存档

A 方案不改 `LANG_KEY`、不改取值集合，**无迁移**。老值 `both` / `zh` / `yue` 全部继续有效，
只是 `both` 的行为变了（正是本次要改的）。

## 7 如果还要再进一步（B：真删一档）

在 A 全部落地、跑过一轮之后，若仍觉得按钮多：

1. `LANG_MODES = ["yue", "zh"]`；`LANG_LABEL` 去掉 both。
2. **必须加迁移**（否则老的 both 玩家回退到粤语）：
   ```js
   const l = localStorage.getItem(LANG_KEY);
   if (l === "both") langMode = "zh";        // 老 both → 新的「普通话（带对照）」
   else if (LANG_MODES.includes(l)) langMode = l;
   else langMode = "yue";
   ```
3. `talkBody` 的 `showZh` 从 `mode === "both"` 改成 `mode === "zh"`。
4. 文案：`LANG_LABEL.zh = "普通话"`（语义已是「普通话 + 对白原文」）。

代价：只想要一行普通话的玩家没有了。要不要留，是产品决定，不是技术决定。

**新脚本 `tools/扫粤语.mjs`（建议写，半小时）**：在 zh/both 下依次打开 hub／对白／网页／日记簿／
聊天／地图，收集所有文本节点，报两类：

- 港繁残留：`toHkTrad(s) !== s`（应只在「角色对白主行」出现）

**四道检查**：`全检.mjs`（可加一条：选项 label 夹粤语告警）、`门检.mjs`、`门外核对.cjs`、`冒烟.cjs`。

确认对话框不溢出、不出现「的。」单独一行（这是 390 下踩过的老坑）。

## 9 需要作者定的三件事

1. **旁白算不算「对话」？** 本方案算「她想到的」→ 普通话。若算对话，则旁白也要
   「港繁 + 小字」，一屏会出现「旁白两行 / 对白两行」交替，更乱。**建议按本方案。**
