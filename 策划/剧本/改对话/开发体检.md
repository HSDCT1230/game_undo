## 二、本轮已修的两处

### 1. 续玩卡 `6 / 17`

`levels.js` 的 `resumeCaption`：

```js
(PARTS[cur.part] || "") + "　·　" + curN + " / " + (LEVELS.length - 1),
```

`LEVELS` 下标从 1 起、`[0]` 是 `null`，`Object.keys()` 会把它算进去。已改，实测显示 `6 / 16`。

### 2. 390px 顶栏日期换行

`style-chrome.css`：`#clock` 补 `white-space: nowrap`；`@media (max-width: 420px)` 里把时钟降到 10.5px、`os-opt` 内边距收到 `1px 3px`、环境音按钮 6.4em → 5.8em。

实测 390×844：`暗度　2014年8月1日 夜｜自動 關｜粵語｜字 中｜環境音 大` 一行放得下，不再折行、不再被 32px 条裁掉半行。

## 三、P0：对话中刷新 = 整关重来

**复现**

1. `index.html?level=6&seg=e`（诊室对白中段）
2. 点两句，触发 `saveProgress()`（`pagehide` / `visibilitychange` 会自动触发，手机切个 App 就够）
3. 重开 `index.html` → 出现「继续」→ 点下去

**现象**：不是回到刚才那句，而是回到第 6 关的**开场卡**（「終於有人肯聽…」），整段诊室对白要重看。

**原因**（两段代码咬在一起）

```js
// levels.js —— 存档时把 talk 剔掉，但 mode 还是 "talk"
const SKIP_KEYS = ["talk", "wait", "paused", "modal", "card", "diaryLeaf", "clinic"];
```

```js
// levels.js —— 读档时看到 mode="talk" 就走 draw()
} else if (S.mode && S.mode !== "card" && S.mode !== "end") {
  draw();
}
```

```js
// talk.js —— S.talk 已被剔掉，直接 return，舞台是空的
function drawTalk() {
  const t = S.talk;
  if (!t) return;
```

空舞台 → `recoverEmptyStage()` → `enterLevel(6)` → 开场卡。状态（flags／笔记／证物）没丢，丢的是"这一段看到哪儿"。

**为什么不能简单把 talk 也存进去**：`beats` 数组里混着函数（`goto`、`then`、`act`），`JSON.stringify` 会把它们丢掉，恢复出来是一段点不动的死对白。

**三种修法，按成本排**

| 方案 | 做法 | 成本 | 风险 |
| --- | --- | --- | --- |
| A（建议先做） | 存档时把 `mode: "talk"` 改写成"可重入"的状态，并在字幕卡上说一句「这一段从头开始」 | 半天 | 低 |
| B | 每个对话场记一个 `talkFrom`（场景函数名＋句号），恢复时重放场景函数再快进到第 i 句 | 2–3 天 | 中：场景函数带副作用，要逐个确认幂等（`note`／`fileEvidence` 已按 id 去重，`S.chatLogs` 没有） |
| C | 每推进 10 句写一个关卡内检查点（只存 flags＋场景名），恢复时从最近检查点重放 | 3–5 天 | 中高 |

> 现在手机上一关最长的一段是 `clinic4Talk`（64 句，6–8 分钟）。切出去回个微信就全没了，这是最容易被玩家记成"这游戏有 bug"的一类。

## 四、P1：资源重量

### 4.1 缩略图用原图

走动界面（`?level=3`）一屏 8 个热点，DOM 实测：

```
示意-大门与铁闸  natural 1152×864  →  显示 197×86
示意-全家福      natural 1152×864  →  显示 197×86
...
```

`object-fit: cover`，等于把 4:3 的图裁成 2.3:1 的一条，**97% 的像素从来没被看见**。这 7 张原图合计 **8.1MB**（不含 810KB 的底图）。同样的显示尺寸，做成 400×175 的 JPEG 每张约 8–12KB，一屏可以从 8MB 降到 80KB。

### 4.2 全库图片

| 项 | 数 |
| --- | --- |
| 张数 | 190 |
| 总量 | 198.3MB |
| 平均 | 1.03MB |
| 最大 | 2.9MB（`示意-日历-0813-对街的人.png`） |
| 16:9（1280×720） | 79 张 |
| 4:3（1152×864） | 67 张 |
| 其它比例 | 44 张 |

全部是 PNG 存照片。照片类内容换 JPEG q85（或 WebP q80）通常压到 **1/8–1/10**，198MB 大约能到 20–25MB，画质在 1080p 上看不出差别。

### 4.3 音频

51 个 mp3、共 58MB。环境声是长循环，单首 1.6–3.8MB：

```
3.8MB  环境-澄心诊室.mp3
3.6MB  环境-澄心候诊.mp3
3.0MB  环境-天台.mp3
2.8MB  环境-澄心诊室-第10关.mp3
```

浏览器是边下边播，首声不会等整首，但**部署包体和手机流量**是实打实的。降到 96kbps 单声道，体积大约 1/3，环境声听不出差别。

### 4.4 没有加载态

`imgSlot()` 只有「图到了就显示」和「图挂了显示待补图」两种状态，中间几秒是空白。8MB 一屏在 4G 上就是 5–8 秒的空白格。

## 五、P2：资产与工程卫生

### 5.1 重复图 50MB

md5 比对：**19 组重复、46 个多余文件、浪费 50.1MB**。

```
2030KB ×2  荣汇街-天台.png / 场景-天台.png
1754KB ×3  示意-坐在厅里盯两分钟 / 示意-拿出门前的照片来比 / 示意-玩具车又转了
1615KB ×2  表姐家.png / 场景-美娟家.png
1441KB ×2  荣汇街-平台.png / 场景-前座门口.png
```

其中 `场景-候诊.png` 有 3 份完全相同、`场景-诊室.png` 有 4 份完全相同——因为 `LV_HAVE` 要求每关自己的文件夹里都有这张图。**要省这 50MB，得让 `lvPic` 支持"只登记一次、各关共用"，这会动 `全检` 的登记规则**，不是删文件就能了事。

### 5.2 23 张"假 PNG"

`墙簿/` 下 9 张头像和另外 14 张，扩展名 `.png`、文件头是 `FF D8 FF`（JPEG）。浏览器靠嗅探能显示，但：

- 静态服务器会发 `Content-Type: image/png`，多数浏览器仍然能显示，个别工具链／CDN 会当成坏图；
- 头像显示尺寸约 40–60px，原图 260–360KB，一页墙簿 2.7MB。

### 5.3 6 张孤儿图（2.8MB）

没有任何 `.js/.css/html` 引用：

```
1491KB  16-天台-9月8日/场景-结局-陈倒下.png
 501KB  04-第一夜-8月14日夜/_p_cars2.png
 298KB  _p_场景-拨999.png
 256KB  04-第一夜-8月14日夜/_p_car.png
 182KB  _p_荣汇街-厅-夜里.png
 137KB  03-搬进来-8月1日至13日/_p_key.png
```

`场景-结局-陈倒下` 是"结局改纯文字"之前留下的；`_p_` 前缀那几张看命名是过程稿。

### 5.4 版本控制

`git status`：**115 个改动 + 10 个新增未提交**，最后一次提交是「收进当前可玩稿…」。上一轮那一批改动（交纸、等待卡、已读、自动播放）也全在工作区里，没有落盘到历史。

> 这是目前**风险最高的一条工程项**：任何一次误操作／磁盘问题，都不可恢复。

### 5.5 其它

- `assets/s2hk.js.bak`（33KB）——仓库里留着手工备份。
- `story.js` / `web.js` / `style.css` 是 3 个"已拆分，不要加载"的占位文件，留着能解释历史，但也容易被误改。
- `游戏/assets/img/` 只有一个 README，实际图库在仓库根的 `图/`。新人第一次打包 `游戏/` 会得到一版全白图。

## 八、测试盲区

`tools/全检.mjs`（380 行）做得很扎实：语法、图引用、`LV_HAVE` 登记、每关底图、放大配字、粤普混写、Flag 有没有后果、Ink 对账。但它**全是静态的**，下面这些一条都盖不到——上一轮那个 `23:NaN` 就是从这里漏出去的：

- 每关能不能真的做完（`levelReady` 在所有任务路径上都可达）
- 存档往返（关内刷新、跨关选关、旧档迁移）
- 移动端布局（换行、裁切、安全区）
- 资源体积与首屏时间
- 运行时异常（现在只有 `drawCard`/`loadSave` 局部 try/catch，没有全局兜底）

**建议加三个脚本**（都能用现成的 `tools/_bin/cdp-*.cjs` 改）：

1. `smoke-levels.cjs`：逐关 `enterLevel` + 点掉开场卡 + 断言舞台非空、无 console 报错。（上一轮手工做过，值得固化）
2. `save-roundtrip.cjs`：在 talk／hub／web／wait 四种 mode 下各存一次、重开、断言落点符合预期。（这次的问题就是它该抓的）
3. `perf-budget.cjs`：统计每关图片总字节，超过阈值（比如 3MB）就报错。
