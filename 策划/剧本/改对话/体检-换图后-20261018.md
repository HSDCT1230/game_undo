## 五、没做成的一件事：全自动通关

本来想写个机器人从头点到结局，替掉"手动通一遍"。做了三轮，**没做成，如实记下来**：

- 纯点 DOM 的机器人能过卡片、对白、hub 热点，但卡在**网页关卡**（第 1 关就要"顶帖 → 搜荣汇街 → 开盘 → 留言"这条有序链）。
- 网页里可点元素太多（导航、页签、列表、侧栏），盲点会在 `home / list / forum / rules` 之间来回跳，跑了 1500 多次点击仍在第 1 关。
- 加了「正路关键词加权 + 访问过的状态加重惩罚」也没走通。要真正跑通，得**逐关写操作脚本**（16 关约 80 步），成本远高于收益。

**替代方案已经落地**：`tools/冒烟.cjs` 用游戏自带的 `SEGS` 分段表，把 49 个可达入口各进一次各点十下，覆盖了几乎全部界面状态，且全部干净。**这套能挡住"白屏／坏图／报错"，挡不住"流程死锁"**——某一步该出现的按钮没出现，只有真人点一遍才发现。所以还差一次人工通关。

## 五之二、替那次人工通关先做两件事

自动跑不通，就把"人跑"的成本压到最低。做了两件，都已入库：

**1. 生成了一份逐关核对清单**：`策划/剧本/改对话/通关核对清单.md`（341 行）。
它不是手抄的，是 `tools/通关清单.mjs` 直接从 `levels.js` 的 `tasks` 数组里抽出来的，
改关卡后重跑一条命令就同步，不会和代码脱节。内容：

- 一张全表：16 关的篇／标题／时间／地点／★ 必做项数／○ 可选项数／分段入口名；
- 每关一段：★ 必做按顺序编号，带 `after` 的标出"触发"（那一段画面的名字），带 `hint` 的附上提示原话；
- 合计 **★ 必做 50 项、○ 可选 30 项**——把这 50 项点出来，主线就是通的。

**2. 静态核了一遍这 50 道门有没有"永远开不了"的**：`tools/门检.mjs`。
它把每个 `need: true` 项的 `done()` 源码取出来，抽出里面读的条件名，再回所有 asset 里数这个名字被写过几次。**结论：没有死门。**

```
== 门检 ==
  必做项 50 项：具名条件核到 36 处、属性式 8 处，覆盖 41 项；余 9 项是计数式，静态查不出，只能实际点
  死门（读得到、没人写）：0
```

几个容易看着像"查无此人"、其实没问题的：

- `S.handed.ok6 / ok8 / ok10 / ok12` 是 `S.handed["ok" + n] = true`（`diary.js:470`）动态拼的键，静态 grep 搜 `"ok6"` 一定搜不到；
  `CLINIC_DAY` 的键正好是 6／8／10／12 四个，与四次交纸一一对上。
- `S.visitSeen[2/3/4]` 是 `S.visitSeen[visit] = true`（`story-clinic.js:124`）。
- `S.clinicLooked.drawer4` 是 `L.drawer4 = true`（`story-clinic.js:31`），键是变量不是字符串。

剩下 9 项是**计数式**（"屋里看清四样东西""诊室里看三样"这类靠热点凑数），静态查不出来——只能人去点。
所以这份结论的边界很清楚：**不存在"必做项永远满足不了"的死锁；风险只剩"条件满足了但按钮没画出来"和"热点点不动"，
这两类只有照清单实际点。**
