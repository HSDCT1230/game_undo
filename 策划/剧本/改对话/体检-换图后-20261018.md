## 七、10-19 收尾：图库转 JPEG

第四节排的四件图库卫生，这一轮全部落地。核心一句：**这批图是照片，用 PNG 存等于完全不压缩**，换个容器就把 193.7MB 变成 26.7MB，画面肉眼无差。

### 动手之前先证了一件事

185 张里 102 张标称 `RGBA`、看着像"有透明通道"，但逐张读 alpha 通道的极值，**全部是 255，没有一张真透明**。
所以整批可以无损地去掉 alpha 转 JPEG，不会有哪张图的镂空变成黑底。这一步没做的话，转完得一张张回头看，反而更慢。

### 参数怎么定的

| 方案 | 全库体积 |
| --- | --- |
| q82 4:2:0 | 18.0MB |
| **q88 4:4:4** | **26.7MB** |
| q90 4:4:4 | 更大，且 PSNR 只多 1–2dB |

选 q88 并且**关掉色度抽样（4:4:4）**，不是因为爱惜体积，是因为图库里有一批**截图类图片**——预约表、租盘列表、墙簿、证件——
上面是繁体小字。4:2:0 会把色度分辨率砍半，繁体字的竖笔和细横会在色块边缘糊掉，这种劣化在手机上特别明显。
q90 试过，只多 3MB 左右但 PSNR 提升已经进入平台期（36–45dB），不值。目视验过 `示意-预约表`：
「預約表 / 日期 姓名 / 8月16日 週六 / 阿文 / 章慧琪」全部清晰可读。

### 换图工作流没有变

只改了 `游戏/assets/pics.js` 一处：

```js
const PIC_EXT = "jpg";   // 原来拼的是 "png"
```

`picSrc()` 是**全库唯一的读图入口**，所有图都过它，所以改这一个常量就够了，19 个 JS 文件里没有别处拼后缀。
以后想换某张图，流程照旧：**同名覆盖**，然后跑一句

```
python tools/压图.py
```

它会转成 `.jpg` 并把原 `.png` 删掉。忘了跑也不会悄悄当成缺图——`全检.mjs` 会直接报「图库里有未转换的 PNG」，
如果同一张图两种格式并存，它还会单独报一条。这道护栏是这次特意加的，因为"图片莫名不显示"是这类改动最常见的坑。

### 三道护栏

1. `tools/压图.py` —— 转换器。默认 q88 / 4:4:4 / progressive / optimize；`--dry` 只算不写、`--keep` 只生成不删源文件、`--quality N` 换画质。
2. `tools/_bin/check-jpg.py` —— 转完逐张 `Image.verify()` + 重开取尺寸 + 与转换前记录比对。结果：**可解码 185 张，合计 26.7MB，格式、尺寸、体积全部对得上，没有 `.png` 残留。**
   （唯一一条需要放宽：`藤先生-空头像` 这种 10KB 级的小图，JPEG 的头开销可能比 PNG 还大几 KB，属于正常，不算问题。）
3. `tools/全检.mjs` —— 新增"图库不许有未转换 PNG / 同图两格式并存"两条硬检查，报错文案里的后缀也全改成 `.jpg`。
